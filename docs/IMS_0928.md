## Summary

- **The problem is the network, not our build.** Free here gives voice and incoming SMS only over IMS. The CS
  fallback lands on Orange 3G (20801), which rejects the SIM (`docs/CALL_CAPTURE_0928.txt:38-40`).
- **An open stack exists.** It is **PhhIms**: a userspace SIP/IMS `ImsService`, **GPL-2.0**, written by
  phhusson and actively forked for Samsung Exynos. It needs **no Samsung RIL call**: every branch uses only
  standard Android APIs.
- **A Lineage 22.2 branch already exists** (`ims-for-wisdom` `lineage-22.2`), with no Android-16-only code.
  Its README still says testing happens on 23.x.
- **Our device offers what it needs.** Our RIL serves the standard data, SIM and voice interfaces. The kernel has
  IPsec/xfrm. The stock APN list has Free's `ims` APN.
- **Free has been exercised by the original author.** PHH's IKE proposals are commented "works on Free Mobile
  208 15", but that code is a test activity, not the VoLTE path.
- **Unknown until tried:**
  - whether Free whitelists devices for VoLTE;
  - whether our Samsung audio HAL routes userspace RTP to the earpiece and mic;
  - whether the patch set builds cleanly in the /e/OS tree.
- **Interim without IMS:** force 3G-only and pick Free (20815) by hand. It works only where Free has its own 3G
  coverage, and the log shows it immediately (see "No-IMS interim").

## 3. Voice audio path

- **Today (CS attempt).** The audio HAL logs `*** Started CP Voice Call ***` (`docs/TASK_0928_call.md:26`). The
  modem carries the audio, and the application processor only routes it.
- **With PhhIms.** RTP runs in the app, and the audio is a normal Android `AudioRecord` / `AudioTrack` pair in
  `MODE_IN_COMMUNICATION`:
  - `SipAudioRecordFactory.kt:13-14` and `SipAudioRecordStarter.kt:17`;
  - the downlink forces the same mode before creating its `AudioTrack` (`SipHandler.kt:5206-5208`).
- The fork's README says why: "Some Samsung HALs treat `MODE_IN_CALL` as a modem-call path. For a userspace IMS
  stack, `MODE_IN_COMMUNICATION` may be required" (README:488-492).
  - It says working earpiece/mic "still depends on ROM-side Samsung audio HAL fixes and mixer routing" (:49,
    :478-486).
  - It says the old per-device flag `EXYNOS9810_CALLVOL_FIX` is no longer used (:414, :484).
- **What to check in our configs.** Their contents are not in the reference; only the file list is
  (`device/proprietary-files.txt:40-52`):
  - `audio_policy_configuration.xml`, `primary_audio_policy_configuration.xml` and the **`…_sec_on_gsi.xml`**
    variants (`:43`, `:50`), which Samsung ships for running on a generic AOSP system. Look for a mix port
    flagged `AUDIO_OUTPUT_FLAG_VOIP_RX`, an input usable by the `VOICE_COMMUNICATION` source, and routes to
    `Earpiece` and `Built-In Mic`.
  - `mixer_paths.xml`: paths for communication/VoIP use cases on earpiece and handset mic, as opposed to the
    `incall` / CP paths.
  - Which of the two policy files the HAL actually loads (capture 5).

## 4. Carrier side (Free, carrierId 1958, 208/15)

- **IMS APN.** `ims`, type `ims`, `IPV4V6`, `authtype="1"` (stock `apns-conf.xml:3636-3642`). The ePDG entry also
  uses APN `ims` (stock `epdg_apns_conf.xml:3471-3480`, `mnoname="Free_FR"`).
- **P-CSCF discovery.** Stock Samsung data does not state it. The standard way is P-CSCF addresses returned at IMS
  PDN setup; PhhIms reads them from `LinkProperties` and falls back to ISIM and DNS (section 2).
- **VoWiFi / ePDG.** Stock's Free entry gives remote identity `ims`, IPsec AES-CBC-128/256 with HMAC-SHA1-96 or
  SHA2-256-128, IKE the same, DPD 1800 s (`epdg_apns_conf.xml:3471-3480`).
  - It gives **no ePDG address**, so the default is the 3GPP operator-identifier FQDN
    `epdg.epc.mnc015.mcc208.pub.3gppnetwork.org` (3GPP TS 23.003 §19.4.2.9).
  - PHH's test code uses exactly this family of algorithms: IKE AES-CBC-128 / HMAC-SHA1-96 / MODP-1024, child SA
    AES-CBC-128 / HMAC-SHA1-96, each commented "works on Free Mobile 208 15" (PHH `MainActivity.kt:72-79`,
    `:106-111`).
- **Device whitelisting for VoLTE: unknown.** No public source was opened that states Free's policy. Only a test
  shows it. The Samsung user-agent the stack sends (section 2) is one variable.
- **Current carrier config** (capture): `carrier_volte_available_bool = false`,
  `carrier_wfc_ims_available_bool = false`, `imssms.sms_over_ims_supported_bool = true`
  (`docs/CALL_CAPTURE_0928.txt:60-65`). AOSP's own CarrierConfig source for Free could not be opened: Lineage 22.2
  builds it from AOSP (`default.xml:708`), and `android.googlesource.com` is refused by this environment's network
  policy.
- **Turning VoLTE on:**
  - A device **CarrierConfig overlay** for Free: `carrier_volte_available_bool`, `editable_enhanced_4g_lte_bool`,
    and later the WFC keys (README:366-381).
  - The framework overlay `config_device_volte_available=true`, plus the WLAN service packages for VoWiFi
    (README:320-333).
  - The Telephony overlay `config_ims_mmtel_package=me.phh.ims` (README:335-343).
  - `persist.dbg.volte_avail_ovr=1` / `wfc_avail_ovr=1` are bring-up shortcuts only (README:307-318).
- **When.** In the same build that ships PhhIms and declares `android.hardware.telephony.ims`. Before that, turning
  them on would only expose toggles for a service that does not exist.

## No-IMS interim: stay on Free's own 3G

- **What happens now.** The dial triggers CS fallback. The network (not the phone) redirects the call from LTE to
  a 3G layer, and the phone finds Orange (20801) there. Orange refuses: `REG_DENIED_EM, rat: UMTS,
  reasonForDenial: PLMN_NOT_ALLOWED` (`docs/CALL_CAPTURE_0928.txt:38-40`). No carrier-config key or setting changes
  where the network redirects a CS fallback.
- **What the phone can do** is not use LTE at all, and camp directly on **Free's own UMTS (20815)**:
  1. Set the preferred network type to **WCDMA only**. The phone info menu `*#*#4636#*#*` offers "WCDMA only"
     (LineageOS `android_packages_services_Telephony` `4fe0d708` `src/com/android/phone/settings/RadioInfo.java:146`),
     applied through `setAllowedNetworkTypesForReason` (:2426). This is `NETWORK_MODE_WCDMA_ONLY = 2`
     (`RILConstants.java:160`).
  2. In **Settings > Network > Network operators**, turn off automatic selection and pick Free.
- **Proof in the log:** `< OPERATOR {Free, Free, 20815}` with
  `< VOICE_REGISTRATION_STATE RegStateResult{regState: REG_HOME, rat: UMTS`. A test call then shows
  `UNSOL_RESPONSE_CALL_STATE_CHANGED` and ALERTING.
  - If it shows `REG_DENIED` on 20815 or finds only 20801, Free has no own 3G at this spot and there is no interim.
    Whether it has is not in any source opened.
- **Costs:**
  - no LTE, so data is slower;
  - a manual selection that must be undone when IMS works;
  - the phone info menu is a debug tool, and its setting can be overridden later by the framework.
- **Emergency calls.** They already work in principle: on 20801 the state is `REG_DENIED_EM`, which means
  "emergency calls are enabled" (`RegState.aidl:63-65`), and PhhIms leaves emergency on CS (section 1).
